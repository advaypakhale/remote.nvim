1. INTRODUCTION                                     *remote-nvim-introduction*

remote.nvim installs a Neovim binary, your config, and any tools you declare into
a single directory under `$HOME` on a remote machine or container.

Its config, data, state and cache directories are all redirected into that one
directory, so an existing Neovim on the target keeps its own.

Starting Neovim on the target is left to you. Installing prints the command to
run; see |remote-nvim-layout|.

Installing is idempotent. Running |:Remote| again pushes config changes;
binaries are downloaded only when the version recorded on the target differs
from the one you want.

==============================================================================
2. REQUIREMENTS                                     *remote-nvim-requirements*

Local:
  - Neovim >= 0.11
  - `ssh`
  - `tar`
  - `curl`, used when the target cannot download for itself
  - `docker`, for container targets

Target:
  - a POSIX shell, `tar`, and the usual utilities such as `find`, `cp`, `ln`
    and `id` (busybox versions work)
  - glibc

==============================================================================
3. COMMANDS                                             *remote-nvim-commands*

                                                                     *:Remote*
:Remote                 Prompt for a target and install.

:Remote install [{target}] [{ssh-args}...]
                        Install onto {target}, then print the command to start
                        Neovim there. Prompts when {target} is omitted. Further
                        arguments are passed to `ssh`: >vim

                            :Remote install box -p 2222 -i ~/.ssh/key
<
                        {target} is an ssh host, or `docker:{container}` for a
                        running container.

:Remote! install [{target}]
                        Reinstall binaries even when the target already records
                        the right versions.

:Remote cleanup [{target}]
                        Remove the install directory from {target}, after
                        confirmation.

:Remote! cleanup [{target}]
                        As above, without the confirmation prompt.

Completion offers hosts from your ssh config and running containers.

4. CONFIGURATION                                   *remote-nvim-configuration*

Configuration is optional; the defaults work without calling `setup()`. >lua

    require("remote").setup({
      ssh_config_path = { "~/.ssh/config" },
      config_dir = nil,
      prefix = "~/.remote-nvim",
      app_name = "nvim",
      nvim_version = nil,
      exclude = { ".git" },
      copy_dirs = {},
      tools = {},
    })
<
                                                  *remote-nvim-config-options*
ssh_config_path ~
        `string|string[]`, default `{ "~/.ssh/config" }`
        Files scanned for host names.

config_dir ~
        `string?`, default `nil`
        Config tree to copy to the target. When unset, `stdpath("config")` is
        used, so it follows `NVIM_APPNAME` locally.

prefix ~
        `string`, default `"~/.remote-nvim"`
        Install directory on the target. A leading `~` resolves against the
        target's `$HOME`.

app_name ~
        `string`, default `"nvim"`
        `NVIM_APPNAME` on the target.

nvim_version ~
        `string?`, default `nil`
        Which Neovim release to install. When unset, the local Neovim's
        version is used. Development builds fall back to `"stable"`.

exclude ~
        `string[]`, default `{ ".git" }`
        Patterns excluded from the config tree, passed to `tar --exclude`.
        Set to `{}` to copy everything.

copy_dirs ~
        `table<"data"|"state"|"cache", string[]>`, default `{}`
        Extra directories to copy. See |remote-nvim-copy-dirs|.

tools ~
        `table<string, remote.Tool>`, default `{}`
        Extra binaries to install. See |remote-nvim-tools|.

5. TOOLS                                                   *remote-nvim-tools*

Only Neovim and your config are copied by default. Declare anything else you
want on the target: >lua

    require("remote").setup({
      tools = {
        rg = {
          version = "14.1.1",
          bin = "rg",
          url = function(os, arch)
            return ("https://github.com/BurntSushi/ripgrep/releases/download"
              .. "/14.1.1/ripgrep-14.1.1-%s-unknown-%s-musl.tar.gz")
              :format(arch, os)
          end,
        },
      },
    })
<
Each entry takes:

  url      `fun(os: string, arch: string): string`
           Called with the target's platform. `os` is `"linux"` or `"macos"`,
           `arch` is `"x86_64"` or `"arm64"`.

  bin      `string?`
           Name to locate inside the archive. Defaults to the entry name.
           Ignored when the URL does not end in `.tar.gz` or `.tgz`, in which
           case the download is used as the binary.

  version  `string?`
           Recorded on the target to decide whether to reinstall. Defaults to
           the resolved URL.

A tool is added to the target's `PATH` only when the target does not already
provide it.

6. COPYING PLUGINS                                    *remote-nvim-copy-dirs*

Neovim and declared tools are downloaded by the target when it has `wget` or
`curl`, and otherwise downloaded locally and sent over the connection.

Plugin managers fetch plugins with `git`, which needs network access on the
target. When there is none, copy the plugins you already have: >lua

    require("remote").setup({
      copy_dirs = { data = { "lazy" } },
    })
<
The key names a Neovim directory (`data`, `state` or `cache`) and the values
are subdirectories inside it. The example copies `stdpath("data")/lazy` to the
target's data directory.

A data directory may contain binaries compiled for your platform, such as
treesitter parsers and Mason-installed servers. Copying those to a target with
a different `uname -sm` produces binaries that will not run; a warning is shown
when the platforms differ.

7. LAYOUT ON THE TARGET                                   *remote-nvim-layout*

Everything lives under `prefix`, `~/.remote-nvim` by default: >

    ~/.remote-nvim/
      nvim/{version}/       Neovim, keyed by version
      bin/                  declared tools
      tools/                symlinks added to PATH
      config/{app_name}/    your config
      data/  state/  cache/ XDG directories
      rnvim                 launcher that sets the environment and runs Neovim
      manifest              installed versions and target platform
<
The config directory is replaced on every run, so files deleted locally also
disappear on the target. Plugins live in `data/`, so this does not trigger a
reinstall.

`rnvim` is what you run to start Neovim on the target. It sets `NVIM_APPNAME` and
the four XDG variables, puts any installed tools on `PATH`, and execs the Neovim
binary: >

    ssh -t myserver ~/.remote-nvim/rnvim
    docker exec -it mycontainer ~/.remote-nvim/rnvim
<

==============================================================================
8. LIMITATIONS                                       *remote-nvim-limitations*

- Alpine and other musl systems are not supported, because Neovim publishes no
  musl build.
- Windows is not supported as the local machine.
- `devcontainer.json` is not supported. Attaching to a running container works.
